L'API OpenAI est parmi les infrastructures les plus puissantes sur lesquelles vous pouvez construire. C'est aussi, à l'échelle de production, l'une des lignes de dépense les plus lourdes de votre budget infrastructure. Les équipes le découvrent souvent brutalement — quand la facture mensuelle arrive et affiche trois fois l'estimation.

La bonne nouvelle : la quasi-totalité des surcoûts OpenAI est structurelle, pas fondamentale. Elle provient d'un nombre limité de patterns identifiables et corrigibles. Voici les sept techniques les plus efficaces, par ordre d'impact.

## Tarification OpenAI en 2026

Avant d'optimiser, connaissez ce que vous payez :

L'écart entre GPT-4o et GPT-4o mini est de **33x** sur les tokens d'entrée. La plupart des applications utilisent GPT-4o pour des tâches que GPT-4o mini gère aussi bien — et cet écart se compound à l'échelle.

## Technique 1 : Passer à GPT-4o mini pour les tâches simples

Le changement le plus rapide et à plus fort impact. GPT-4o mini gère la classification, l'extraction d'entités, la détection d'intention, le résumé court et la génération de sortie structurée avec une qualité indiscernable de GPT-4o pour ces types de tâches.

```python
from openai import OpenAI

client = OpenAI()

def classifier_ticket(texte: str) -> str:
    """
    GPT-4o mini est parfaitement capable de cette tâche.
    Passer de GPT-4o économise 97 % sur ce type de requête.
    """
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # Était : "gpt-4o"
        messages=[
            {"role": "system", "content": "Classifiez en : facturation, technique, ou général."},
            {"role": "user",   "content": texte}
        ],
        max_tokens=10,
        temperature=0
    )
    return response.choices[0].message.content.strip()
```

Faites une évaluation sur 200 requêtes réelles avant et après le changement. Pour les tâches de classification et d'extraction, la différence de qualité est rarement perceptible.

**Économies attendues : 30 à 60 % sur les types de requêtes concernés.**

## Technique 2 : Réduire les fenêtres de contexte

Chaque token dans votre prompt système et votre historique de conversation est facturé à chaque requête. Les prompts système grandissent organiquement — ce qui démarrait à 200 tokens est souvent à 2 000+ après six mois d'itérations.

```python
import tiktoken

def auditer_et_reduire(messages: list[dict], modele: str = "gpt-4o-mini") -> dict:
    enc = tiktoken.encoding_for_model(modele)
    ventilation = {}
    for i, msg in enumerate(messages):
        contenu = msg.get("content", "")
        tokens = len(enc.encode(contenu))
        ventilation[f"{msg['role']}_{i}"] = tokens
    
    ventilation["total"] = sum(ventilation.values())
    return ventilation

# Avant optimisation :
# system_0 : 1 847 tokens
# user_1   :   142 tokens
# Total    : 1 989 tokens → 0,00995 $/requête au tarif GPT-4o

# Après réécriture du prompt :
# system_0 :   312 tokens
# user_1   :   142 tokens
# Total    :   454 tokens → 0,00227 $/requête
# Économie : 77 % sur ce type de requête
```

**Économies attendues : 20 à 50 % sur les coûts de tokens d'entrée.**

## Technique 4 : Mettre en cache les requêtes répétées

De nombreuses applications de production envoient des requêtes quasi-identiques à répétition. Les bots de support client voient les mêmes questions chaque jour. Un cache sémantique simple peut éliminer 20 à 40 % des appels API.

```python
import hashlib

_cache: dict[str, str] = {}

def completion_avec_cache(prompt: str, modele: str = "gpt-4o-mini") -> str:
    cle = hashlib.sha256(f"{modele}:{prompt}".encode()).hexdigest()
    
    if cle in _cache:
        return _cache[cle]
    
    response = client.chat.completions.create(
        model=modele,
        messages=[{"role": "user", "content": prompt}]
    )
    resultat = response.choices[0].message.content
    _cache[cle] = resultat
    return resultat
```

**Économies attendues : 15 à 40 % sur les workloads répétitifs.**

## Technique 5 : Définir des plafonds budgétaires stricts

Sans plafond strict, un seul agent en boucle ou une boucle infinie peut consommer le budget d'un mois en quelques heures.

```python
PLAFOND_USD = 500.00

async def verifier_budget(tokens_estimes: int, modele: str) -> None:
    TARIFS = {"gpt-4o": 0.005, "gpt-4o-mini": 0.00015}
    tarif = TARIFS.get(modele, 0.005)
    cout_estime = (tokens_estimes / 1000) * tarif
    
    depense_courante = await db.get_depense_mensuelle("projet-x")
    
    if depense_courante + cout_estime > PLAFOND_USD:
        raise ValueError(
            f"Plafond atteint : ${depense_courante:.2f} / ${PLAFOND_USD:.2f} utilisés."
        )
```

**Économies attendues : prévient les événements catastrophiques.**

## Technique 6 : Surveiller le coût par endpoint

Les totaux mensuels cachent le problème. Le coût par endpoint le révèle. Si votre endpoint d'analyse de documents coûte 0,18 $ par requête pendant que votre classification coûte 0,002 $, vous avez une cible d'optimisation claire.

```python
import logging
from openai.types.chat import ChatCompletion

logger = logging.getLogger("couts_llm")

def logger_cout(response: ChatCompletion, endpoint: str, modele: str) -> None:
    TARIFS = {
        "gpt-4o":      {"entree": 5.0,  "sortie": 15.0},
        "gpt-4o-mini": {"entree": 0.15, "sortie": 0.60},
    }
    tarifs = TARIFS.get(modele, TARIFS["gpt-4o"])
    usage = response.usage
    cout = (
        usage.prompt_tokens * tarifs["entree"] / 1_000_000 +
        usage.completion_tokens * tarifs["sortie"] / 1_000_000
    )
    logger.info("cout_llm", extra={
        "endpoint": endpoint,
        "modele": modele,
        "tokens_entree": usage.prompt_tokens,
        "tokens_sortie": usage.completion_tokens,
        "cout_usd": round(cout, 6),
    })
```

**Économies attendues : révèle des opportunités d'optimisation de 20 à 40 %.**

## Questions fréquentes

### GPT-4o mini est-il aussi bon que GPT-4o ?

Pour de nombreuses tâches, oui. Classification, extraction, sortie structurée, détection d'intention et résumé court fonctionnent à parité ou quasi-parité avec GPT-4o mini. Le raisonnement complexe, la génération longue nuancée et la revue de code sur de grandes bases de code sont là où GPT-4o a un avantage réel. L'approche pratique : évaluez sur votre workload spécifique avec un échantillon de 200 requêtes représentatives.

### Le cache fonctionne-t-il avec le chat conversationnel ?

Le cache exact-match ne fonctionne pas — chaque tour de conversation est différent. Le cache sémantique peut aider pour les questions d'ouverture fréquentes ou les interactions de type FAQ où l'intention est constante même si le wording varie. Pour la plupart des applications de chat, le plus grand gain est dans la réduction du contexte (supprimer l'ancien historique) plutôt que dans le cache.
