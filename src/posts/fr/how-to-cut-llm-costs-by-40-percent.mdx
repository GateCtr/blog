Les dépenses d'inférence LLM augmentent de façon exponentielle. Les équipes qui démarrent avec quelques centaines de dollars par mois se retrouvent rapidement à plusieurs milliers, sans changement notable de leur usage perçu. Ce n'est pas une question de volume — c'est une question de structure.

Il existe trois causes profondes qui expliquent la quasi-totalité des surcoûts LLM. Chacune est corrigible. Et le plus souvent, elles peuvent être corrigées sans modifier une seule ligne de votre code applicatif.

## Cause 1 : Des fenêtres de contexte qui grossissent sans contrôle

Chaque token envoyé dans un prompt est facturé. Les prompts système commencent petits — 100, 200 tokens — puis grossissent organiquement au fil des ajustements et des cas limites traités. Six mois plus tard, le même système prompt en contient 2 000.

L'historique de conversation est encore plus problématique. Une application qui envoie l'historique complet à chaque requête paie de façon linéaire avec le nombre de tours. Une conversation de 20 échanges à 400 tokens chacun représente 8 000 tokens d'entrée — rien que pour l'historique.

```python
import tiktoken

def auditer_contexte(messages: list[dict], modele: str = "gpt-4o") -> None:
    enc = tiktoken.encoding_for_model(modele)
    tarifs = {"gpt-4o": 5.0, "gpt-4o-mini": 0.15}
    tarif = tarifs.get(modele, 5.0)
    
    total = 0
    for msg in messages:
        tokens = len(enc.encode(msg.get("content", "")))
        cout = tokens * tarif / 1_000_000
        print(f"{msg['role']:10} | {tokens:6} tokens | ${cout:.5f}/requête")
        total += tokens
    
    cout_total = total * tarif / 1_000_000
    print(f"\nTotal : {total:,} tokens → ${cout_total:.4f} par requête")
    print(f"À 100 000 requêtes/jour : ${cout_total * 100_000:.0f}/jour")
```

**Correction :** Auditer le prompt système et le réduire de façon agressive. Implémenter un historique glissant (conserver uniquement les 4 à 6 derniers échanges). La plupart des équipes réduisent leurs tokens d'entrée de 50 à 70 % avec ces deux actions seules.

## Cause 2 : Le même modèle coûteux pour toutes les requêtes

GPT-4o coûte 5 $ par million de tokens en entrée. GPT-4o mini coûte 0,15 $ — soit 33 fois moins. La plupart des applications utilisent GPT-4o pour tout, y compris pour des tâches que GPT-4o mini gère avec la même qualité.

Classification, extraction d'entités, détection d'intention, résumé court, génération de JSON structuré — toutes ces tâches fonctionnent à parité de qualité avec GPT-4o mini. Les utiliser sur le bon modèle représente en pratique 40 à 60 % du volume total de requêtes.

```python
CARTE_MODELES = {
    "classification":    "gpt-4o-mini",   # 0,15 $/M tokens
    "extraction":        "gpt-4o-mini",   # 0,15 $/M tokens
    "resume_court":      "gpt-4o-mini",   # 0,15 $/M tokens
    "generation_code":   "claude-3-7-sonnet",  # via gateway
    "raisonnement":      "o3-mini",       # 1,10 $/M tokens
    "defaut":            "gpt-4o",        # 5,00 $/M tokens
}

def obtenir_modele(type_tache: str) -> str:
    return CARTE_MODELES.get(type_tache, CARTE_MODELES["defaut"])
```

**Correction :** Auditer vos types de requêtes. Pour chaque type, tester GPT-4o mini sur 200 exemples réels et mesurer la qualité. Dans la majorité des cas, il n'y a pas de différence perceptible.

## Cause 3 : Aucune limite budgétaire stricte

Sans plafond strict, un agent en boucle ou une erreur de configuration peut consommer le budget d'un mois en quelques heures. Ce scénario n'est pas rare — il arrive à des équipes sérieuses, avec du code de production testé.

```python
PLAFOND_QUOTIDIEN_USD = 200.00

async def verifier_budget(agent_id: str, tokens_estimes: int, modele: str) -> None:
    TARIFS = {"gpt-4o": 0.005, "gpt-4o-mini": 0.00015}
    tarif = TARIFS.get(modele, 0.005)
    cout_estime = (tokens_estimes / 1000) * tarif
    
    depense_courante = await db.get_depense_quotidienne(agent_id)
    
    if depense_courante + cout_estime > PLAFOND_QUOTIDIEN_USD:
        raise RuntimeError(
            f"Plafond budgétaire atteint pour {agent_id} : "
            f"${depense_courante:.2f} / ${PLAFOND_QUOTIDIEN_USD:.2f}. "
            "Requête bloquée."
        )
```

**Correction :** Définir des plafonds stricts au niveau du compte (dans le dashboard OpenAI) et au niveau de l'application (par agent, par utilisateur, par projet). Les deux couches sont nécessaires.
