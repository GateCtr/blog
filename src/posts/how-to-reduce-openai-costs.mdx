OpenAI's API is among the most capable infrastructure you can build on. It is also, at production scale, one of the most expensive line items in your infrastructure budget. Teams routinely discover this the hard way — when the monthly invoice arrives and the number is three times the estimate.

The good news: most OpenAI overspend is structural, not fundamental. It comes from a handful of identifiable, fixable patterns. Here are the seven most effective techniques, in order of impact.

## Technique 1: Switch to GPT-4o mini for Simple Tasks

The fastest, highest-impact change you can make. GPT-4o mini handles classification, entity extraction, intent detection, short summarization, and structured output generation with quality that is indistinguishable from GPT-4o for these task types.

```python
from openai import OpenAI

client = OpenAI()

def classify_support_ticket(text: str) -> str:
    """
    GPT-4o mini is perfectly capable of this task.
    Switching from GPT-4o saves 97% on this request type.
    """
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # Was: "gpt-4o"
        messages=[
            {"role": "system", "content": "Classify as: billing, technical, or general."},
            {"role": "user", "content": text}
        ],
        max_tokens=10,
        temperature=0
    )
    return response.choices[0].message.content.strip()
```

Run a quality evaluation on a sample of 200 real requests before and after the switch. For classification and extraction tasks, the quality difference is rarely detectable.

**Expected savings: 30–60% on applicable request types.**

## Technique 2: Trim Context Windows

Every token in your system prompt and conversation history is billed on every request. System prompts grow organically over time — what started as 200 tokens is often 2,000+ after six months of iteration.

```python
import tiktoken

def audit_and_trim(messages: list[dict], model: str = "gpt-4o-mini") -> dict:
    enc = tiktoken.encoding_for_model(model)
    breakdown = {}
    for i, msg in enumerate(messages):
        content = msg.get("content", "")
        tokens = len(enc.encode(content))
        breakdown[f"{msg['role']}_{i}"] = tokens
    
    breakdown["total"] = sum(breakdown.values())
    return breakdown

# Before optimization:
# system_0: 1,847 tokens
# user_1: 142 tokens
# Total: 1,989 tokens → $0.00995/request at GPT-4o pricing

# After system prompt rewrite:
# system_0: 312 tokens  
# user_1: 142 tokens
# Total: 454 tokens → $0.00227/request
# Savings: 77% on this request type
```

**Expected savings: 20–50% on input token costs.**

## Technique 4: Cache Repeated Queries

Many production applications send near-identical requests repeatedly. Customer support bots see the same questions daily. Internal tools re-process the same documents. A simple semantic cache can eliminate 20–40% of API calls entirely.

```python
import hashlib
from functools import lru_cache

# Simple exact-match cache for high-frequency identical prompts
_cache: dict[str, str] = {}

def cached_completion(prompt: str, model: str = "gpt-4o-mini") -> str:
    cache_key = hashlib.sha256(f"{model}:{prompt}".encode()).hexdigest()
    
    if cache_key in _cache:
        return _cache[cache_key]
    
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}]
    )
    result = response.choices[0].message.content
    _cache[cache_key] = result
    return result
```

For semantic caching (matching similar but not identical prompts), libraries like `langchain` or `GPTCache` provide embedding-based similarity matching with a configurable threshold.

**Expected savings: 15–40% on repetitive workloads.**

## Technique 5: Set Hard Budget Limits

Without hard limits, a single runaway agent or infinite loop can consume an entire month's budget in hours. OpenAI provides account-level spend limits, but per-project and per-user limits require your own implementation.

```python
import asyncio
from decimal import Decimal

HARD_CAP_USD = 500.00  # Monthly cap for this project

async def check_budget(estimated_tokens: int, model: str) -> None:
    """Block the request if it would exceed the monthly cap."""
    PRICING = {"gpt-4o": 0.005, "gpt-4o-mini": 0.00015}
    rate = PRICING.get(model, 0.005)
    estimated_cost = (estimated_tokens / 1000) * rate
    
    current_spend = await db.get_monthly_spend("project-x")
    
    if current_spend + estimated_cost > HARD_CAP_USD:
        raise ValueError(
            f"Budget cap reached: ${current_spend:.2f} of ${HARD_CAP_USD:.2f} used."
        )
```

**Expected savings: prevents catastrophic overrun events.**

## Technique 6: Monitor Cost Per Endpoint

Monthly totals hide the problem. Cost per endpoint reveals it. If your document-analysis endpoint costs $0.18 per request while your classification endpoint costs $0.002, you have a clear optimization target.

Add cost logging to every LLM call:

```python
import logging
from openai.types.chat import ChatCompletion

logger = logging.getLogger("llm_costs")

def log_completion_cost(response: ChatCompletion, endpoint: str, model: str) -> None:
    PRICING = {
        "gpt-4o": {"input": 5.0, "output": 15.0},
        "gpt-4o-mini": {"input": 0.15, "output": 0.60},
    }
    rates = PRICING.get(model, PRICING["gpt-4o"])
    usage = response.usage
    cost = (
        usage.prompt_tokens * rates["input"] / 1_000_000 +
        usage.completion_tokens * rates["output"] / 1_000_000
    )
    logger.info(
        "llm_cost",
        extra={
            "endpoint": endpoint,
            "model": model,
            "input_tokens": usage.prompt_tokens,
            "output_tokens": usage.completion_tokens,
            "cost_usd": round(cost, 6),
        }
    )
```

Aggregate this by endpoint weekly. The results are almost always surprising.

**Expected savings: surfaces optimization opportunities worth 20–40%.**

## Frequently Asked Questions

### Is GPT-4o mini as good as GPT-4o?

For many tasks, yes. Classification, extraction, structured output, intent detection, and short summarization all perform at parity or near-parity with GPT-4o mini. Complex reasoning, nuanced long-form generation, and code review in large codebases are where GPT-4o genuinely pulls ahead. The practical approach: run a quality evaluation on your specific workload with a representative sample of 200 requests.

### Does caching work with conversational chat?

Exact-match caching does not — every conversation turn is different. Semantic caching can help for common opening questions or FAQ-style interactions where the intent is consistent even if the wording varies. For most chat applications, the bigger win is context trimming (removing old history) rather than caching.
